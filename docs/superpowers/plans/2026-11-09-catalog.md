# Catalog (Milestone 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browsable, searchable, filterable exercise library with detail pages and a credits screen, built from a reproducible import of two open datasets and filtered by the user's equipment by default.

**Architecture:** A Node import script merges Workout Guide (illustrated) and free-exercise-db (text-only, plus level and instructions where names match) into one validated catalog JSON with per-field provenance. The app lazy-loads that JSON, filters it with pure functions, and reads the user's equipment from the existing `user_settings` table. Generated data and images are build outputs, not committed.

**Tech Stack:** Existing stack (React, TypeScript, Vite, Tailwind, shadcn, TanStack Query, Zod, Supabase, Vitest + RTL). New dev dependency: `@bryllim/workout-guide` (source of frames and metadata) and `tsx` (run TypeScript scripts).

**Spec:** `docs/superpowers/specs/2026-11-09-workout-tracker-design.md` (sections 5 and 7). PRD: `.claude/prds/workout-tracker.prd.md` (milestone 2).

## Global Constraints

- UI language English only. No medical claims; no exercise is called safe, suitable or recommended for a person. "Suggested" means: normalized equipment is a non-empty subset of {bodyweight, wall, chair} AND a source states level `beginner`.
- Never invent data. A field missing from every source is `null` or empty and shown as "not available", never filled in. Exercises with no level are never labelled beginner.
- Every field group carries provenance (source name, id, URL, license, author). Content written by this project is marked `project` and `reviewStatus: "unreviewed"`.
- Only licensed images ship: Workout Guide frames (CC BY-SA 4.0, 3 PNG frames, 512x512). free-exercise-db images are never used or copied (unknown license). Do not recompress or edit frames (any change must be documented under CC BY-SA 4.0).
- No external CDN at runtime; images are served from `public/exercises/`.
- Source licenses: Workout Guide code MIT, art CC BY-SA 4.0 (76 frames derive from Everkinetic, CC BY-SA 4.0, per-frame attribution in its `manifest.json`); free-exercise-db Unlicense (maintainer statement; images unlicensed).
- Catalog IDs are deterministic: `wg-<slug>`, `fed-<id lowercased>`, `project-<slug>`. Removed exercises are marked `deprecated`, never deleted from the output.
- Normalized vocabularies are shared across sources. Equipment values: `bodyweight, wall, chair, pull-up-bar, doorway, towel, box, bench, dumbbell, barbell, kettlebell, machine, cable, bands, plate, medicine-ball, stability-ball, foam-roll, e-z-bar, cardio-machine, other`. Unknown/null equipment stays `[]` (unknown) and never counts as available.
- Generated outputs (`src/data/exercise-catalog/catalog.json`, `credits.json`, `review-report.md`, `public/exercises/`) are gitignored and rebuilt by `npm run catalog:build`, which also runs as `predev` and `prebuild`. Tests use small fixtures, not the generated files.
- TDD for every task. Supabase is mocked in tests. TypeScript 7: no `baseUrl`.
- Verify the `@bryllim/workout-guide` and free-exercise-db shapes against the real files before coding (field names recorded in the spec, section 5); do not guess.

## Review Focus

1. Exercise with unknown/null equipment: never shown as available for the user's equipment and never "suggested". (Tasks 1, 5)
2. Exercise with no level or no instructions: detail page says "not available", the level badge is absent, and nothing is labelled beginner. (Tasks 4, 8)
3. Missing or failing image: card and detail show a placeholder and layout does not break. (Tasks 7, 8)
4. Search: accents and punctuation are ignored ("push up" finds "Push-up"), empty query lists everything, and no matches shows an empty state with a clear-filters action. (Tasks 5, 7)
5. Unknown exercise id in the URL shows a not-found state; a user with no `user_settings` row gets the defaults (bodyweight, wall, chair) instead of an error. (Tasks 6, 8)

### Task 3: Matching and merge

**Files:**

- Create: `scripts/catalog/match.ts`
- Test: `scripts/catalog/match.test.ts`

**Interfaces:**

- Consumes: `WgRaw`, `FedRaw` (Task 2), `normalizeMuscle` (Task 1).
- Produces: `normalizeName(s: string): string` (lowercase, strip accents and punctuation, collapse spaces, singularize a trailing "s" on the last word only for matching); `matchExercises(wg: WgRaw[], fed: FedRaw[]): Match[]` where `Match = { wgId: string; fedId: string; confidence: 'exact' | 'fuzzy'; score: number }`. Each side matches at most once. `exact` = equal normalized names. `fuzzy` = token-set similarity at least 0.85 AND same normalized primary muscle; fuzzy matches are returned but flagged.

- [ ] **Step 2: Run** the tests. Expected: FAIL.
- [ ] **Step 3: Implement** `normalizeName` and `matchExercises` (greedy best-score assignment, deterministic ordering).
- [ ] **Step 4: Run** tests. Expected: PASS. Then run it on the real data and record counts (expected around 51 exact; report fuzzy count) in the commit body.

**Interfaces:**

- Consumes: Tasks 1-3.
- Produces: `buildCatalog(input: { wg: WgRaw[]; fed: FedRaw[]; project: ProjectRaw[]; now: string }): { catalog: Catalog; credits: Credits; review: string }` (pure, deterministic for the same input; sorted by `id`). `Credits = { sources: { name: string; url: string; license: string; note: string }[]; frames: { exerciseId: string; creator: string; license: string; sourceUrl?: string; changes?: string }[] }`.
