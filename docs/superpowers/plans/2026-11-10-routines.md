# Routines (Milestone 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can use and edit starter routines A/B/C, or build their own routines from the catalog, with data stored per user in Supabase.

**Architecture:** Two RLS-protected tables (`routines`, `routine_exercises`) plus two SQL functions that make writes atomic: `save_routine` (create or replace a routine and its exercises in one transaction) and `seed_starter_routines` (idempotent first-run copy of the starters, guarded by a flag on `user_settings`). The app keeps a pure draft model (`routineDraft.ts`) for editing, TanStack Query hooks for server state, and the existing catalog filter for the exercise picker.

**Tech Stack:** Existing stack (React, TypeScript, Vite, Tailwind, shadcn, TanStack Query, Zod, Supabase, Vitest + RTL, Lucide). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-workout-tracker-design.md` (sections 6, 7, 8 and 11). PRD: `.claude/prds/workout-tracker.prd.md` (milestone 3). Visual language: bone palette, `page-title` / `section-title` utilities in `src/styles/index.css`.

## Global Constraints

- UI language English only. No medical claims: nothing is called safe, suitable or recommended for a person. Starter routines are labelled "Starter" and described as a suggestion the owner can edit, never as advice.
- Never invent catalog data. A starter exercise whose catalog entry has no level shows no level badge. Nothing is labelled beginner without a source (spec section 5).
- Starter exercises are real catalog ids only (verified 2026-11-10 against the generated catalog).
- Every table enables RLS with policies on `auth.uid()`; schema changes are numbered SQL files in `supabase/migrations` (next number: `0002`). Only the publishable key is used in the app.
- Exercises are referenced by stable catalog id. A routine may reference an id missing from today's catalog (deprecated or renamed); the app must not crash on it.
- Targets: `sets` 1-10, `reps` 1-100, `seconds` 5-600, `rest_seconds` 0-600, routine name 1-60 characters after trimming, day label one of `A`-`G` or none.
- TDD for every task. Supabase is mocked in tests. TypeScript 7: no `baseUrl`. Alias `@/` maps to `src/`.
- Streaks, badges and "Start workout" belong to later milestones; this plan adds none of them.

## Review Focus

1. A saved routine references an exercise id that is not in the catalog: the editor and list show "Exercise no longer available", the row can still be moved or removed, and saving keeps it. (Task 6)
2. The starter seed runs twice (React StrictMode, two tabs): exactly three starter routines exist afterwards. (Tasks 1, 5)
3. The owner deletes every routine: the starters do not come back on the next visit. (Tasks 1, 5)
4. Saving fails mid-way (network or server error): the routine on the server is unchanged, the editor keeps the draft and shows an error with a retry. (Tasks 1, 6)
5. Invalid numbers (0 sets, blank or non-numeric reps, 10000 seconds) and a blank name: the editor blocks saving and says which field is wrong. (Tasks 3, 6)

### Task 1: Migration, RLS and atomic functions

**Files:**

- Create: `supabase/migrations/0002_routines.sql`
- Modify: `scripts/verify-rls.mjs`

**Interfaces:**

- Produces (SQL, used by Task 4):
  - Table `routines(id uuid pk default gen_random_uuid(), user_id uuid not null references auth.users on delete cascade, name text not null check (char_length(name) between 1 and 60), day_label text check (day_label in ('A','B','C','D','E','F','G')), is_starter boolean not null default false, created_at timestamptz not null default now(), updated_at timestamptz not null default now())`
  - Table `routine_exercises(id uuid pk default gen_random_uuid(), routine_id uuid not null references routines on delete cascade, user_id uuid not null references auth.users on delete cascade, position int not null, exercise_id text not null, sets int not null check (sets between 1 and 10), target_type text not null check (target_type in ('reps','seconds')), target int not null check (target between 1 and 600), rest_seconds int not null check (rest_seconds between 0 and 600))`, unique `(routine_id, position)`.
  - Column `user_settings.starters_seeded boolean not null default false`.
  - `public.save_routine(p_id uuid, p_name text, p_day_label text, p_items jsonb) returns uuid`: when `p_id` is null inserts a routine, otherwise updates the owner's routine (raises if not found); deletes the routine's exercises and inserts `p_items` (array of `{exercise_id, sets, target_type, target, rest_seconds}`, position = array index) in the same transaction; returns the routine id. `security invoker`.
  - `public.seed_starter_routines(p_routines jsonb) returns boolean`: if the caller's `user_settings.starters_seeded` is false (creating the settings row with defaults when absent), inserts each element of `p_routines` (`{name, day_label, items}`) with `is_starter = true`, sets the flag, returns true; if already true returns false and inserts nothing. Row-locks the settings row so concurrent calls cannot both seed.

**Interfaces:**

- Consumes: `getSupabase()` from `@/lib/supabase`; `useSession()`; `STARTER_ROUTINES`; `Routine`, `Draft`.
- Produces (same patterns as `useSettings.ts`: query key includes the user id, errors thrown as `new Error(message)`):
  - `useRoutines(): { routines: Routine[]; isLoading: boolean; error: Error | null }`: selects `routines` with nested `routine_exercises` ordered by `position`; routines ordered by `day_label` (nulls last) then `created_at`.
  - `useRoutine(id: string): { routine: Routine | null | undefined; isLoading: boolean }` (`null` = not found).
  - `useSaveRoutine()`: mutation taking `{ id: string | null; draft: Draft }`, calls `rpc('save_routine', { p_id, p_name, p_day_label, p_items })`, returns the routine id, invalidates the routines queries.
  - `useDeleteRoutine()`: mutation taking `id: string`, deletes the `routines` row, invalidates the list.
  - `useDuplicateRoutine()`: mutation taking a `Routine`, calls `save_routine` with `p_id: null` and name `"<name> (copy)"` truncated to 60 characters, `dayLabel: null`.
  - `useSeedStarters()`: mutation with no arguments, calls `rpc('seed_starter_routines', { p_routines: STARTER_ROUTINES mapped to snake_case })`, invalidates the list.
